## Project Overview

Clinical Review Scheduler is a healthcare scheduling application for managing clinical review assignments across multiple entities and employees. Built with React 18, Vite, Firebase (Firestore + Auth), and Tailwind CSS.

**Key capabilities**: Employee/entity management, schedule creation with draft/publish workflow, assignment history tracking, conflict detection, auto-save, undo/redo, workload balancing, Excel export, analytics dashboards.

## Architecture

### Application Context Hierarchy

The app uses a layered context provider structure (see `src/App.jsx`):
```
EnhancedErrorBoundary
  └── ThemeProvider (dark/light mode)
      └── AuthProvider (Firebase authentication)
          └── UserPreferencesProvider (user settings)
              └── Router (react-router-dom with basename="/ClinicalReviewScheduler")
                  └── Routes
```

**Critical**: The app uses a basename of `/ClinicalReviewScheduler/` for GitHub Pages deployment. All routes are prefixed with this.

### Routing Structure

- `/schedule` - Public view (default, no auth required)
- `/login` - Supervisor login page
- `/supervisor` - Main supervisor dashboard (protected)
- `/analytics` - Analytics dashboard (protected)
- `/productivity` - Productivity tracking (protected)
- `/insights` - Advanced insights (protected)

Protected routes use `<ProtectedRoute>` component which checks `isSupervisor` from `useAuth` hook.

### Data Model & Firebase Collections

**Firestore Collections** (defined in `src/constants/index.js`):
- `schedules` - Schedule documents with status ('draft' | 'published')
- `employees` - Employee records with skills array
- `entities` - Location/facility records
- `settings` - App configuration (e.g., `darConfig` document)
- `auditLogs` - Audit trail of all changes (auto-generated by `AuditService`)

**Skills System**: Employees have skills: `['DAR', 'Trace', 'CPOE', 'Float']`
- Float = trained in all tasks
- Skills determine which assignment columns are available in schedule grid

**Schedule Structure**: Each schedule contains:
- `name`, `startDate`, `endDate`, `status`
- `assignments` - nested object keyed by employee ID
- `darConfig` - entity-specific DAR counts
- `darCount` - default DAR count (default: 5)
- `createdAt`, `updatedAt`, `createdBy`

### State Management Patterns

**No Redux/Zustand** - Uses React hooks + Context:
- `useAuth()` - Authentication state (currentUser, isSupervisor, login/logout)
- `useToast()` - Toast notifications (showSuccess, showError, showConfirm)
- `useAutoSave()` - Auto-save with 2-second debounce
- `useUndoRedo()` - Undo/redo history management (up to 50 changes)
- `useConflictDetection()` - Real-time validation of schedule conflicts

**Local State Pattern**: Most data is loaded fresh from Firebase on page load and stored in component state. SupervisorDashboard is the primary state container.

### Key Utilities & Services

**Validation** (`src/services/validationService.js`):
- Uses Zod schemas from `src/schemas/`
- Always validate data before Firebase operations
- Schemas: `scheduleSchema`, `employeeSchema`, `entitySchema`, `auditLogSchema`

**Conflict Detection** (`src/utils/conflictDetection.js`):
- Detects skill mismatches, double assignments, workload imbalances
- Returns conflicts with severity levels: 'error' (red), 'warning' (yellow), 'info' (blue)
- Used by `ConflictBanner` component and `useConflictDetection` hook

**Audit Trail** (`src/services/auditService.js`):
- `AuditService.log()` - Logs all schedule/employee/entity changes to Firestore
- Captures action type, userId, before/after state, timestamp

**Logging** (`src/utils/logger.js`):
- **Always use logger instead of console**: `logger.info()`, `logger.warn()`, `logger.error()`
- Provides structured logging with timestamps and context

**Export** (`src/utils/exportUtils.js`):
- `exportScheduleToExcel()` - Exports schedule with workload summary to Excel using `xlsx` library

### Component Organization

**Page Components** (`src/pages/`):
- `SupervisorDashboard.jsx` - Main supervisor view with tabs (Schedule, Employees, Settings)
- `UserView.jsx` - Public read-only schedule view

**Reusable Components** (`src/components/`):

## Code Patterns & Conventions

### Imports from Constants
Always use constants from `src/constants/index.js`:
```javascript
import { COLLECTIONS, SCHEDULE_STATUS, SKILLS } from '../constants';

// Good
collection(db, COLLECTIONS.SCHEDULES)
schedule.status === SCHEDULE_STATUS.PUBLISHED

// Bad - magic strings
collection(db, 'schedules')
schedule.status === 'published'
```

### Firebase Operations
Always use centralized patterns:
```javascript
import { collection, getDocs, query, orderBy } from 'firebase/firestore';
import { db } from '../firebase';

// Always handle errors
try {
  const snapshot = await getDocs(query(collection(db, COLLECTIONS.EMPLOYEES), orderBy('name')));
  // ...
} catch (error) {
  logger.error('Error loading employees:', error);
  showError('Failed to load employees');
}
```

### Validation Pattern
```javascript
import { validateSchedule } from '../services/validationService';

// Validate before saving
const validation = validateSchedule(scheduleData);
if (!validation.success) {
  logger.error('Validation failed:', validation.errors);
  showError('Invalid schedule data');
  return;
}
```

### Audit Logging Pattern
```javascript
import { AuditService } from '../services/auditService';

// Log all mutations
await AuditService.log({
  action: 'update_schedule',
  entityType: 'schedule',
  entityId: schedule.id,
  userId: currentUser?.uid,
  before: oldSchedule,
  after: newSchedule
});
```

### Component Patterns
- **Always use functional components with hooks**
- Add PropTypes to all components
- Use `logger` instead of `console.*`
- Handle loading states with `<DashboardSkeleton />` or `<Skeleton />`
- Wrap mutations in try/catch with toast notifications

## Special Features

### Auto-Save System
- `useAutoSave` hook provides 2-second debounced saving
- Shows "Saving...", "Saved", or error status via `<AutoSaveIndicator />`
- Warns on page navigation with unsaved changes

### Undo/Redo System
- Keyboard shortcuts: Ctrl+Z (undo), Ctrl+Y (redo), Ctrl+Shift+Z (redo on Mac)
- Managed by `undoRedoManager.js` utility
- History stack limited to 50 changes to prevent memory issues
- Integrated with schedule editing via `useUndoRedo` hook

### Conflict Detection
- Real-time validation as assignments change
- Conflict types:
  - **Skill mismatch**: Employee assigned to task they're not trained for
  - **Double assignment**: Employee assigned to multiple entities
  - **Workload imbalance**: Employee >150% or <50% of average workload
- Visual feedback via `<ConflictBanner />` with expandable details

### Accessibility
- **WCAG 2.1 AA compliant** (see `ACCESSIBILITY.md`)
- Keyboard navigation support throughout
- ARIA labels and live regions via `<AriaLiveRegion />`
- Focus management in modals via `useFocusTrap` hook
- Screen reader tested

## Common Pitfalls

1. **Don't use magic strings** - Always import from `src/constants/index.js`
2. **Don't use console.*** - Use `logger` from `src/utils/logger.js`
3. **Don't skip validation** - Always validate with Zod schemas before Firebase writes
4. **Don't forget audit logs** - Use `AuditService.log()` for all mutations
5. **Don't forget error handling** - Wrap Firebase operations in try/catch
